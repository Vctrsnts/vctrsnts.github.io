Proteger la API de CUP con Traefik para su uso desde Homepage

Introducción

El objetivo de esta configuración es proteger el acceso a la API de CUP mediante BasicAuth de Traefik, manteniendo la posibilidad de utilizar CUP desde un servidor local con Homepage.

La arquitectura utilizada es:

VPS ├── Traefik ├── CUP └── PocketID

Servidor local └── Homepage

Homepage consulta la API de CUP mediante:

/api/v3/json

La preocupación inicial era que CUP estuviera expuesto a Internet y que cualquiera pudiera consultar la información sobre los containers del VPS.

1. Configuración original de CUP

El docker-compose.yml original de CUP tenía:

services: cup: image: ghcr.io/sergi0g/cup:latest container_name: cup restart: unless-stopped networks: - proxy command: -c /config/cup.json serve volumes: - /run/user/1002/podman/podman.sock:/var/run/docker.sock:ro - ${PODMAN_STORAGE_PATH}/.config/cup/cup.json:/config/cup.json healthcheck: test: - CMD - /cup - –version interval: 60s timeout: 10s retries: 3 start_period: 20s labels: - traefik.enable=true - traefik.http.services.cup.loadbalancer.server.port=8000 - traefik.http.routers.cup.rule=Host(${FQDN}) - traefik.http.routers.cup.entrypoints=websecure - traefik.http.routers.cup.tls.certresolver=myresolver

networks: proxy: external: true

2. Configuración de Homepage

Homepage utilizaba el widget customapi para consultar CUP:

  • CUP: icon: /icons/cup-with-straw.png href: https://cupsdocker.VPS.duckdns.org description: Notifications for New Container Version Releases siteMonitor: https://cupsdocker.VPS.duckdns.org widget: type: customapi url: https://cupsdocker.VPS.duckdns.org/api/v3/json refreshInterval: 10000 method: GET mappings: - field: metrics: monitored_images label: Monitored images format: number - field: metrics: up_to_date label: Up to date format: number - field: metrics: updates_available label: Available updates format: number

3. Creación del middleware BasicAuth

Se decidió proteger únicamente la API de CUP mediante un middleware de Traefik.

El middleware se añadió al archivo dinámico de Traefik:

middlewares.yml

El middleware creado se denominó:

cup-api-auth

La configuración utilizada fue:

http: middlewares:

# ...

cup-api-auth:
  basicAuth:
    users:
      - "cup-api:HASH"

El HASH corresponde al hash generado para BasicAuth.

La contraseña en texto plano no se almacena en la configuración.

4. Middlewares existentes

El archivo middlewares.yml ya contenía otros middlewares:

http: middlewares:

rate-limit-50:
  rateLimit:
    average: 50
    burst: 100
    period: 1m

retry-3:
  retry:
    attempts: 3
    initialInterval: 500ms

compresionHeaders:
  compress:
    excludedContentTypes:
      - text/event-stream
      - application/x-xz

A este archivo se añadió:

cup-api-auth: basicAuth: users: - “cup-api:HASH”

5. Creación de un router específico para la API

En lugar de aplicar BasicAuth al router principal de CUP, se creó un segundo router exclusivamente para:

/api/v3/json

Se añadieron las siguientes labels:

Router protegido de la API

  • traefik.http.routers.cup-api.rule=Host(${FQDN}) && Path(/api/v3/json)
  • traefik.http.routers.cup-api.entrypoints=websecure
  • traefik.http.routers.cup-api.tls.certresolver=myresolver
  • traefik.http.routers.cup-api.middlewares=rate-limit-50@file,cup-api-auth@file
  • traefik.http.routers.cup-api.service=cup

La línea:

  • traefik.http.routers.cup-api.service=cup

indica que el router cup-api utiliza el servicio de Traefik llamado cup.

Este servicio ya estaba definido mediante:

  • traefik.http.services.cup.loadbalancer.server.port=8000

Por tanto, no fue necesario crear ningún servicio adicional.

6. Configuración actual de las labels

Las labels de CUP quedaron así:

labels:

  • traefik.http.services.cup.loadbalancer.server.port=8000

  • traefik.http.routers.cup-api.service=cup

7. Comprobación desde el dashboard de Traefik

En el dashboard de Traefik se comprobó que existen dos routers:

cup@docker cup-api@docker

El router:

cup@docker

no tiene ningún middleware asociado.

El router:

cup-api@docker

sí tiene asociados:

rate-limit-50@file cup-api-auth@file

Por tanto, cup-api-auth@file no está asociado al router principal de CUP.

8. Comprobación de la interfaz web

Se comprobó el acceso a:

https://cupsdocker.VPS.duckdns.org/

mediante curl.

La respuesta fue:

HTTP/2 200

Esto demuestra que la interfaz web de CUP no está protegida por cup-api-auth.

El router principal:

  • traefik.http.routers.cup.rule=Host(${FQDN})

continúa funcionando sin middleware.

9. Comprobación de la API sin autenticación

Se realizó la siguiente prueba:

curl -vk https://cupsdocker.VPS.duckdns.org/api/v3/json

La respuesta fue:

HTTP/2 401 www-authenticate: Basic realm=“traefik”

Esto confirma que el middleware:

cup-api-auth@file

está funcionando correctamente.

Un cliente que intente acceder a la API sin credenciales recibe:

401 Unauthorized

10. Comprobación de la API con autenticación

También se comprobó el acceso utilizando las credenciales de BasicAuth:

curl -i
-u “cup-api:CONTRASEÑA”
https://cupsdocker.VPS.duckdns.org/api/v3/json

La API respondió correctamente.

Por tanto:

Sin credenciales → 401 Con credenciales → 200

11. Problema descubierto

Durante las pruebas apareció un comportamiento importante.

Aunque la URL:

/

no está protegida, la interfaz web de CUP realiza posteriormente peticiones a su propia API:

/api/v3/json

El flujo es:

Firefox │ ▼ / │ ▼ CUP │ │ consulta su API ▼ /api/v3/json │ ▼ router cup-api │ ▼ cup-api-auth@file │ ▼ 401

Esto provoca que Firefox muestre el diálogo de autenticación Basic.

La situación se comprobó también desde las herramientas de desarrollo del navegador: la interfaz de CUP intenta acceder a la API y es en ese momento cuando aparece la solicitud de usuario y contraseña.

12. Estado actual

La configuración actual protege correctamente la API para Homepage, pero tiene un efecto secundario.

Homepage

Homepage │ ▼ /api/v3/json │ ▼ BasicAuth │ ▼ CUP

Funciona correctamente.

Interfaz web de CUP

Firefox │ ▼ CUP web │ ▼ /api/v3/json │ ▼ BasicAuth

La propia interfaz web de CUP solicita autenticación.

Por este motivo, no se han realizado más modificaciones.

13. Configuración que NO se ha realizado

Hasta este punto:

  • No se ha creado un segundo dominio para la API.
  • No se ha modificado la configuración DNS.
  • No se ha añadido PocketID al router de CUP.
  • No se ha eliminado BasicAuth.
  • No se ha modificado la configuración interna de CUP.

La configuración actual se mantiene tal cual está mientras se estudia la solución definitiva.

14. Posible solución planteada, todavía NO aplicada

Como posible solución se planteó utilizar un hostname independiente para la API destinada a Homepage.

Por ejemplo:

cupsdocker.VPS.duckdns.org

para la interfaz web y:

cupsdocker-api.VPS.duckdns.org

para Homepage.

La idea sería que Homepage utilizase:

url: https://cupsdocker-api.VPS.duckdns.org/api/v3/json

y que Traefik protegiese ese segundo hostname con:

cup-api-auth@file

Sin embargo, esta solución todavía no se ha implementado.

Antes de introducir más cambios en Traefik, se ha decidido comprobar cómo está resolviendo esta situación otra instalación de CUP con una arquitectura similar.

Estado final

La configuración actual es:

                     INTERNET
                        │
                        ▼
                     Traefik
                        │
          ┌─────────────┴─────────────┐
          │                           │
     cup@docker                 cup-api@docker
          │                           │
      Host(FQDN)              Host(FQDN)
                                  +
                           /api/v3/json
                                      │
                          ┌───────────┴───────────┐
                          │                       │
                     rate-limit-50         cup-api-auth
                          │                       │
                          └───────────┬───────────┘
                                      │
                                      ▼
                                     CUP

Resultado

  • La interfaz web de CUP responde con 200.
  • La API /api/v3/json está protegida con BasicAuth.
  • Homepage puede autenticarse contra la API.
  • Un acceso externo sin credenciales a la API recibe 401.
  • La protección de la API interfiere con la propia interfaz web de CUP.
  • No se han realizado todavía cambios adicionales para solucionar esta última cuestión.
