Pero antes de todo esto, lo primero y más importante es la instalación y securización de Memos.

◇ Instalación del container

Aquí tenéis el compose.yml que estoy utilizando:

services:
  memos:
    image: neosmemo/memos:stable
    container_name: memos
    restart: unless-stopped
    init: true
    networks:
      - proxy
    volumes:
      - ${PODMAN_STORAGE_PATH}/.config/memos:/var/opt/memos
    environment:
      MEMOS_DRIVER: sqlite
    labels:
      - traefik.enable=true
      - traefik.http.services.memos.loadbalancer.server.port=5230
      - traefik.http.routers.memos.entrypoints=websecure
      - traefik.http.routers.memos.tls.certresolver=myresolver
      - traefik.http.routers.memos.rule=Host(`${FQDN}`)
networks:
  proxy:
    external: true
x-dockge:
  urls:
    - https://{FQDN}

Además, para las variables, como por ejemplo {FQDN}, lo tengo de la siguiente manera:

PODMAN_STORAGE_PATH=/home/tu_usuario
FQDN=memos.tu.servidor.org

Ahora únicamente nos queda iniciar el container, que, a través de Dockge, es tan sencillo como darle al play y ya tenemos Memos en funcionamiento.

◈ Accediendo a Memos

Llegados a este punto, ya tenemos Memos funcionando. Ahora toca pensar en cómo quiero acceder a él.

Mi idea es utilizar PocketID como sistema de autenticación, tal como hago ahora con Traefik o Beszel. El flujo sería el siguiente:

               ┌──────────────┐
               │   Pocket ID  │
               └──────┬───────┘
                      │
                     OIDC
                      │
                      ▼
               ┌──────────────┐
               │    Memos     │
               │              │
               │ ┌──────────┐ │
               │ │ Password │ │ ← sigue habilitado
               │ └──────────┘ │
               │              │
               │ ┌──────────┐ │
               │ │ Pocket ID│ │ ← SSO
               │ └──────────┘ │
               └──────────────┘

Es decir, me autentico en PocketID y, una vez validado el acceso, entro en Memos.

De momento, eso sí, quiero mantener habilitado el acceso mediante usuario y contraseña.

Nota

A lo mejor, en un futuro, desactivo la opción de usar usuario / password y dejo únicamente el acceso mediante PocketID. Tengo que estudiarlo.

◈ Configurando PocketID

Lo primero es configurar en PocketID el acceso para Memos. En esta web podemos ver los pasos que hay que seguir, pero, en resumen, lo que tenemos que hacer es lo siguiente:

  • Vamos a Pocket ID, donde creamos un nuevo cliente OIDC que podemos llamar Memos.
  • Podemos añadir el logo del cliente OIDC, que sería el de Memos y que podemos encontrar aquí.
    • Buscamos por Memos y copiamos la URL de la imagen que queremos utilizar (PNG, WEBP).
  • Establecemos la URL callback como https://< Memos Host >/auth/callback.
  • Una vez introducidos los datos, tenemos que conservar:
    • Client ID
    • Client Secret
    • URL EndPoint de autorización
    • URL EndPoint del token
    • URL EndPoint del usuario

Con esto ya hemos terminado con PocketID. Ahora pasamos a Memos.

◈ Configurando Memos

Para configurar Memos, tenemos que seguir estos pasos:

  • Accedemos a Memos con la cuenta del administrador.
  • Vamos a Settings → SSO → Hacemos Create.
  • En la opción Template seleccionamos Custom.

Y hasta aquí podemos llegar, porque no nos deja modificar esta opción ni continuar con el proceso de configuración.

Después de esta decepción, me puse a buscar información sobre cómo continuar con el proceso para tener disponible PocketID con Memos. Según ChatGPT y la documentación de Memos, la única opción es mediante el archivo memos-idp-pocket-id.json, pero, para ello, antes tenemos que hacer una modificación en nuestro archivo compose.yml de Memos.

Tenemos que añadir la opción:

    volumes:
      - ${PODMAN_STORAGE_PATH}/.config/memos/secrets:/etc/secrets:ro

Y este fichero tiene que contener la siguiente información:

{
  "uid": "pocket-id",
  "name": "Pocket ID",
  "type": "OAUTH2",
  "identifierFilter": "",
  "config": {
    "oauth2Config": {
      "clientId": "CLIENT_ID",
      "clientSecret": "CLIENT_SECRET",
      "authUrl": "URL_AUTHORIZATION",
      "tokenUrl": "URL TOKEN",
      "userInfoUrl": "URL_USER_INFO",
      "scopes": [
        "openid",
        "profile",
        "email"
      ],
      "fieldMapping": {
        "identifier": "sub",
        "displayName": "name",
        "email": "email",
        "avatarUrl": "picture"
      }
    }
  }
}

Ponemos este archivo dentro de, en mi caso, .config/memos/secrets y reiniciamos el container. Con ello ya tenemos la integración de Memos con PocketID. Pero esto no me parece muy seguro: tener un archivo con la información de conexión entre Memos y PocketID. Y, por lo que parece, no hay otra manera de hacerlo.

Pero no me podía creer que la configuración se hiciera de esta manera. Busqué más información al respecto, pero no encontré nada. Así que se me ocurrió una locura 😈 y funcionó.

¿Y si usamos una versión anterior a la que estamos utilizando (0.30.0)?

Para ello, detenemos el contenedor, borramos la base de datos, modificamos la versión del contenedor a la versión 0.29.1 y volvemos a iniciar el contenedor con esta versión.

Tendremos que reiniciar el proceso de creación de usuario y todo lo demás, pero, a la hora de llegar a la creación del SSO, todo funcionó tal como indica la documentación de PocketID. Podía modificar el Template y seleccionar Custom.

Reiniciamos el proceso que viene en la documentación de PocketID:

  • Accedemos a Memos con la cuenta del administrador.
  • Vamos a Settings → SSO → Hacemos Create.
  • En la opción Template seleccionamos Custom.
  • Introducimos el ClientID.
  • Introducimos el ClientSecret.
  • Introducimos el Authorization EndPoint.
  • Introducimos el Token URL.
  • Introducimos el Userinfo URL.
  • Establecemos los Scopes que nos indican: openid email profile.
  • Establecemos el Identifier como preferred_username.
  • En Display ponemos profile.
  • En Email ponemos email.

Solamente nos queda guardar la configuración y probar que todo ha ido bien. Y así fue. Desde PocketID podía acceder a Memos.

Lo único que hice después fue desactivar la opción de:

En mi caso lo hago porque voy a ser el único usuario que utilice Memos.

Lo que no he hecho yo ha sido desactivar la opción Disallow password auth:

Porque, en el caso de que quisiéramos acceder con el usuario administrador, no podríamos. Eso ya os lo dejo a vuestra libre elección.

◇ Actualización

Una vez que ya tenía todo en funcionamiento, lo que me preocupaba era que estaba utilizando una versión antigua, la 0.29.1, cuando la actual es la 0.30.0. Asimismo, también me preocupaba que, a la hora de hacer la actualización a la nueva versión, perdiéramos la configuración, porque, tal como hemos visto, en la nueva versión la opción de configurar Template como Custom no es posible en el caso de querer añadir más usuarios.

Pero quien no se arriesga, no gana. Así que actualicé el container a la versión stable, tal como habíamos puesto al principio:

services:
  memos:
    image: neosmemo/memos:stable

Después de modificar la versión, actualizamos el container y todo sigue funcionando sin ningún problema. Se mantenía la configuración Custom y podía acceder a Memos, pero eso sí, tal como he dicho antes, si quiero añadir un nuevo Custom, no se podrá hacer.

Pero, de momento, como soy el único usuario, no tengo ningún problema y, además, estoy en la última versión. Espero que con la siguiente versión esto siga funcionando igual de bien. 🤞
